# Домашняя работа №2

## ArticleFlow: локальный агрегатор статей

> **Не начинайте с чтения всего документа подряд.** Сначала откройте [`START_HERE.md`](START_HERE.md). Там простыми словами разобраны смысл программы, движение данных и порядок реализации. Этот `README` используется как подробный справочник с точными требованиями.

Вам необходимо разработать небольшую, но законченную программу, которая получает статьи от нескольких источников, приводит данные к единому формату, хранит каталог, выполняет поиск и следит за доступностью источников.

В реальном проекте источниками могли бы быть Хабр, корпоративный блог или внешний API. В этой работе сеть не используется: источник представлен обычной функцией. Она возвращает список статей либо `None`, если сервис временно недоступен.

Работа выполняется в IDE. Основной код программы находится в одном файле `article_aggregator.py`; готовый сценарий запуска — в `demo.py`.


## Практический результат

После завершения программа должна поддерживать следующий сценарий:

```python
sources = {
    "habr": fetch_habr,
    "blog": fetch_blog,
}

run = build_application(sources, max_failures=2)

run("fetch", "habr")
run("search", "python", tag="functions")
run("stats")
run("status", "habr")
run("reset", "habr")
```

Переменная `run` — функция-диспетчер. Она принимает имя команды, находит соответствующую функцию и передаёт ей остальные аргументы.

## Какие темы занятия используются

- функция как объект — функции-источники хранятся в словаре;
- позиционные и именованные аргументы — публичные функции имеют заданные сигнатуры;
- `*args` и `**kwargs` — диспетчер передаёт аргументы командам;
- безопасное значение по умолчанию — список тегов не должен быть общим;
- функция высшего порядка — конвейер принимает другие функции;
- замыкание — каталог, команды и мониторы продолжают существовать после завершения `build_application`;
- `nonlocal` — монитор изменяет счётчики между вызовами;
- LEGB — состояние не хранится в глобальных переменных;
- мутация и перепривязка — приложение должно защищать внутренние данные от внешнего изменения.

## Что не требуется

- классы;
- декораторы;
- генераторы;
- обработка исключений;
- реальные HTTP-запросы;
- чтение и запись файлов;
- сторонние библиотеки;
- собственные тесты;
- type hints.

Все команды и имена источников в проверках корректны. Обрабатывать неизвестные команды, неправильные типы и отрицательные значения не нужно.

## Модель данных статьи

Внутри приложения статья имеет следующий вид:

```python
{
    "id": "habr-1",
    "title": "Замыкания в Python",
    "text": "Практическое введение...",
    "source": "habr",
    "tags": ["python", "functions"],
    "metadata": {
        "rating": 42,
    },
}
```

## 1. Создание нормализованной статьи

Реализуйте:

```python
def create_article(article_id, /, title, text, *, source, tags=None, **metadata):
    ...
```

Требования:

1. `article_id` передаётся только позиционно.
2. `source` и `tags` передаются только по имени.
3. У `title` удаляются пробелы по краям, а несколько пробельных символов подряд заменяются одним пробелом.
4. У `text` удаляются пробелы по краям.
5. Теги очищаются от пробелов и переводятся в нижний регистр.
6. Повторяющиеся теги удаляются, порядок первого появления сохраняется.
7. Пустые после очистки теги не добавляются.
8. Исходный список тегов изменять нельзя.
9. Если `tags` не передан, каждый вызов создаёт новый пустой список.
10. Дополнительные именованные значения сохраняются во вложенном словаре `metadata`.

Пример:

```python
article = create_article(
    "habr-1",
    "  Замыкания   в Python ",
    "  Текст статьи.  ",
    source="habr",
    tags=[" Python ", "Functions", "python", "   "],
    rating=42,
)

print(article)
# {
#     "id": "habr-1",
#     "title": "Замыкания в Python",
#     "text": "Текст статьи.",
#     "source": "habr",
#     "tags": ["python", "functions"],
#     "metadata": {"rating": 42},
# }
```

## 2. Конвейер функций

Реализуйте:

```python
def make_pipeline(*functions):
    ...
```

Функция возвращает новую функцию `pipeline(value)`. Она последовательно передаёт результат каждого шага следующей функции.

```python
normalize = make_pipeline(str.strip, str.lower)

print(normalize("  PyThOn  "))  # python
```

Если шагов нет, конвейер возвращает исходное значение. Набор функций должен храниться в замыкании.

В `build_application` используйте `make_pipeline` для преобразования сырой записи источника в нормализованную статью. Проверка результата выполняется автоматически, а использование конвейера может быть дополнительно проверено на защите.

## 3. Монитор доступности источника

Реализуйте:

```python
def make_service_monitor(max_failures, /):
    ...
```

Монитор хранит в замыкании:

- количество успешных обращений;
- количество неуспешных обращений;
- количество последовательных ошибок.

Он возвращает словарь функций:

```python
{
    "record": record,
    "can_call": can_call,
    "status": status,
    "reset": reset,
}
```

Поведение:

- `record(True)` увеличивает число успехов и сбрасывает последовательные ошибки;
- `record(False)` увеличивает общее и последовательное число ошибок;
- `record(...)` возвращает текущее значение `can_call()`;
- `can_call()` возвращает `False`, когда последовательных ошибок стало не меньше `max_failures`;
- `status()` возвращает новый словарь состояния;
- `reset()` обнуляет все счётчики и возвращает новый статус.

Формат статуса:

```python
{
    "successes": 0,
    "failures": 0,
    "consecutive_failures": 0,
    "available": True,
}
```

Глобальные переменные использовать нельзя. Разные мониторы должны быть независимы.

## 4. Сборка приложения

Реализуйте:

```python
def build_application(sources, /, *, max_failures=3):
    ...
```

`sources` — словарь вида:

```python
{
    "habr": fetch_habr,
    "blog": fetch_blog,
}
```

Каждая функция-источник вызывается без аргументов и возвращает:

- список сырых статей при успехе;
- `None`, если источник временно недоступен.

Пример сырой статьи:

```python
{
    "id": "habr-1",
    "title": "  Замыкания   в Python ",
    "text": "  Текст статьи. ",
    "tags": [" Python ", "Functions"],
    "rating": 42,
}
```

Все поля, кроме `id`, `title`, `text` и `tags`, считаются метаданными.

`build_application` должна:

1. создать отдельный монитор для каждого источника;
2. создать пустой каталог статей;
3. создать функции-команды;
4. сохранить команды в словаре;
5. вернуть функцию `run(command, /, *args, **kwargs)`.

Глобальные переменные для каталога, мониторов или команд запрещены.

### Команда `fetch`

Вызов:

```python
run("fetch", "habr")
```

Алгоритм:

1. Если монитор запрещает вызов, источник не вызывается.
2. Если источник вернул `None`, в монитор записывается ошибка.
3. Если источник вернул список, в монитор записывается успех.
4. Каждая сырая статья нормализуется.
5. Статья сохраняется в каталоге по своему `id`.
6. Повторная статья с тем же `id` обновляет существующую запись и не меняет её место в порядке каталога.

Успешный результат:

```python
{
    "status": "ok",
    "source": "habr",
    "received": 2,
    "added": 2,
    "updated": 0,
}
```

Недоступный источник:

```python
{
    "status": "unavailable",
    "source": "habr",
    "received": 0,
    "added": 0,
    "updated": 0,
}
```

Заблокированный источник:

```python
{
    "status": "blocked",
    "source": "habr",
    "received": 0,
    "added": 0,
    "updated": 0,
}
```

### Команда `list`

```python
run("list")
```

Возвращает список всех статей в порядке первого добавления.

Результат должен быть безопасной копией: изменение возвращённой статьи, её `tags` или `metadata` не должно менять внутренний каталог.

### Команда `search`

```python
run("search", query, source=None, tag=None)
```

Правила:

- `query` ищется без учёта регистра в заголовке и тексте;
- пустая строка соответствует всем статьям;
- `source` при передаче ограничивает поиск одним источником;
- `tag` сравнивается без учёта регистра и внешних пробелов;
- фильтры применяются одновременно;
- возвращаются безопасные копии статей в порядке каталога.

Пример:

```python
run("search", "python", source="habr", tag=" FUNCTIONS ")
```

### Команда `stats`

```python
run("stats")
```

Возвращает:

```python
{
    "total_articles": 3,
    "by_source": {
        "habr": 2,
        "blog": 1,
    },
    "available_sources": ("habr", "blog"),
}
```

`by_source` содержит все источники, даже если от них ещё нет статей. `available_sources` сохраняет порядок из исходного словаря `sources`.

### Команда `status`

```python
run("status", "habr")
```

Возвращает статус монитора выбранного источника.

### Команда `reset`

```python
run("reset", "habr")
```

Сбрасывает монитор источника и возвращает статус после сброса. Статьи из каталога не удаляются.

### Команда `commands`

```python
run("commands")
```

Возвращает:

```python
("fetch", "list", "search", "stats", "status", "reset", "commands")
```

### Диспетчер `run`

`run` находит функцию в словаре команд и вызывает её, передавая `*args` и `**kwargs`. Большую цепочку `if/elif` вместо словаря команд использовать не следует.

## Защита внутреннего состояния

Следующие объекты не должны давать внешнему коду возможность изменить приложение:

- исходный словарь `sources` должен быть скопирован при создании приложения;
- сырые статьи источника не должны изменяться;
- `list` и `search` возвращают копии статей;
- `status` возвращает новый словарь;
- два приложения должны иметь независимые каталоги и мониторы.

Достаточно копировать сам словарь статьи, список `tags` и словарь `metadata`. Более глубокие уровни метаданных в проверках не используются.
